# Binary 设计

把常用命令行工具随服务一起分发：构建期把目标平台的预编译产物内嵌进服务可执行文件，运行期物化到 `$HOME/.sandbox-toolkit/bin`，使沙箱内的子进程无需宿主预装、无需联网即可按名字调用。

## 目标与边界

- 目标平台限定为 macOS 与 Linux；没有与目标平台匹配的上游预编译产物即构建失败；
- 沙箱内需要一个可预期的最小工具集，既不能假定宿主已安装，也不能在运行期下载；
- 把预编译产物内嵌进服务可执行文件，运行期释放成真实文件——exec 只能执行文件系统中的文件，内嵌载荷必须先落地；
- 本文只覆盖“工具从哪来、如何变得可执行”；工具如何被执行归 [Process.md](./Process.md)。

## 工具集

| 工具   | 上游                 | 用途                            |
| ------ | -------------------- | ------------------------------- |
| `fd`   | `sharkdp/fd`         | 文件查找                        |
| `rg`   | `BurntSushi/ripgrep` | 递归搜索，默认尊重 `.gitignore` |
| `jaq`  | `01mf02/jaq`         | JSON 查询                       |
| `jq`   | `jqlang/jq`          | JSON 查询                       |
| `uv`   | `astral-sh/uv`       | Python 包与项目管理             |
| `uvx`  | `astral-sh/uv`       | 免安装运行 Python 工具          |
| `deno` | `denoland/deno`      | JS/TS 运行时                    |

- `fd`、`rg` 是核心工具，任何构建都内嵌；
- `jaq`、`jq`、`uv`、`deno` 各对应一个同名 Cargo feature，聚合 feature `binaries` 一次启用全部；未启用则不进入产物；
- `uvx` 与 `uv` 同属 `uv` feature，物化到同一目录：`uvx` 执行同目录的 `uv`，二者是一组。

## 内嵌方式

构建脚本从各上游 release 取与目标平台匹配的预编译产物，读出其中需要的可执行文件，压缩内嵌进服务：

- 资产命名不统一：多数上游按 Rust target 三元组命名，`jq` 按 OS 与架构命名，由构建脚本映射（https://github.com/jqlang/jq）；
- 上游版本钉死在构建脚本中，升级需显式改动；只固定版本，不做下载校验和验证；
- 构建期需要网络，下载结果跨构建缓存复用，重复构建不重新下载，缓存位置可用 `SANDBOX_TOOLKIT_CACHE` 覆盖；
- 内嵌载荷用 zstd 压缩，只为减小服务体积；
- 构建脚本同时内嵌一份清单，记录每个工具**解压后**字节的 blake3 摘要（构建期预计算的签名），供运行期校验。

## 物化模型

- 运行期把内嵌的工具释放成真实文件，落在 `$HOME/.sandbox-toolkit/bin`；
- 该路径只由 `$HOME` 决定，跨重启稳定，可被服务随后启动的沙箱引用；`$HOME` 不可用即启动失败；
- 目录以 `0700` 创建，只承载可执行文件；
- 目录不随进程退出清理，不属于本次构建集合的残留文件保持原样。

## 物化流程

- 服务启动时执行一次，并行展开每个工具，阻塞至全部完成，早于对外服务；
- 每次启动都对每个已落盘文件与内嵌清单比对：一致即跳过重写，不一致或缺失则重新物化；
- 需要写入时，先写同目录下的临时文件，赋予可执行权限后再原子替换到目标名：任何时刻对外可见的都是完整且可执行的产物，重复启动或并发物化都安全；
- 任一工具失败即整体失败。

## 与 exec 的契约

物化目录必须进入子进程的搜索路径，bare 名才能解析到内嵌工具：

- [Process.md](./Process.md) 的 exec、shell、pty 与 [MCP.md](./MCP.md) 的 stdio 子进程，都以“单个可执行 token + 逐项 argv”启动，bare 名依赖路径搜索解析；
- 四者统一以物化目录前置构造子进程的搜索路径，保留调用方或服务端已有的 PATH，使内嵌工具优先于宿主同名工具；
- 传入绝对路径时按该路径直接执行，不经过搜索。

## 失败处理

内嵌产物在物化前已确定，运行期失败只可能来自文件系统：物化目录创建失败、清单或现有文件读取失败、解压或落盘失败、原子替换失败。任一失败向上暴露并终止启动，且不清理已落盘的产物。
